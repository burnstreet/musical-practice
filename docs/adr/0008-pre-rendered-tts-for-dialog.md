# Pre-rendered TTS for the dialog trainer

The dialog trainer needs every role's lines spoken. We render them once on the Admin's machine, commit the MP3s in the production repo under a hash of spoken text and voice, and pack them like the songs. The app ships audio only, no TTS runtime, and works offline. The engine is chosen per role in the production config: XTTS-v2 locally, or OpenAI's speech API.

A listening test on 2026-11-02 compared Piper, Chatterbox Multilingual and XTTS-v2 on the same lines. Piper was too synthetic; Chatterbox produced garbage in some outputs and renders slower than real time; XTTS babbled only when its own sentence splitting was on. Kokoro has no official German model. Browser `speechSynthesis` varies per device and is not offline-safe.

Amended 2026-11-03: the Admin chose OpenAI `gpt-4o-mini-tts` for the 2026 voices, as a second engine. It costs little (the whole 2026 play about 0.50 USD), takes a whole line in one call, follows spoken instructions per role, and plays the inline directions of a line. We first rejected cloud TTS because it sends the copyrighted script out and adds a key; we accept both now: OpenAI does not train on API data by default, and the key lives in the user environment only. OpenAI shuts the model down on 2027-01-06, after the 2026 production; XTTS stays as the fallback.

Amended again the same day: in a listening comparison (XTTS, `gpt-4o-mini-tts`, `gpt-realtime-2.1`, `gpt-realtime-2.1-mini`) the speech model was hardly better than XTTS; `gpt-realtime-2.1` was preferred for most roles, XTTS for two. So a third engine, `openai-realtime`, speaks a line through the Realtime API. It is a conversational model, so the renderer checks the transcript against the text and speaks the line again when words differ.

Consequences: XTTS rendering needs a CUDA machine and stays out of CI; OpenAI rendering needs the key and network, also never in CI. XTTS-v2 is under the Coqui Public Model License, non-commercial only; the production is non-commercial. The renderer chunks long lines for XTTS (at most 250 characters, no tiny chunk), because XTTS cannot take long input and invents sounds on very short input. For OpenAI the inline directions are part of the line hash, so editing a direction renders the line anew.
